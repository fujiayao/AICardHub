# 任务 T12：系统设置、回答规则与限流

| 项 | 内容 |
|---|---|
| 角色 | 后端智能体 |
| 阶段 | 阶段 1：功能并行开发 |
| 参考工作量 | 1 天（按人天估算，智能体通常更快） |
| 开工条件 | T11（鉴权：员工与管理员登录）、T13（知识库引擎：存储与索引） 已合并到 main |
| 依据 | 开发方案 §5.3 模型配置、§6.5、§10；工程框架方案 §7.6 |
| 接口 | settings_get、settings_update、rules_get、rules_update |
| 数据库 | setting、rate_counter |

## 目标

实现 setting 表（含加密存储 API Key）、回答规则读写、三级限流。

## 允许修改

- `server/app/modules/settings/`
- `server/app/core/ratelimit.py`
- `server/tests/`

## 不得修改

apps/（生成目录除外）、server/tests/acceptance/、scripts/、tasks/BOARD.md；server/app/core/ 除非任务卡明确允许

## 验收标准

1. setting 表：模型配置（base_url、api_key 加密、主/备模型名、超时、inline_token_limit、各级限额）、回答规则、禁答话题、敏感词
2. `GET/PUT /admin/settings/{key}`（`settings_get`、`settings_update`），API Key 只写不读（读取时返回掩码）
3. `GET/PUT /admin/rules`（`rules_get`、`rules_update`）：保存时通过 T13 的 store 同步写 kb/_rules/*.md
4. `ratelimit.hit(key, window, limit)`：MySQL `INSERT ... ON DUPLICATE KEY UPDATE` 实现，访客/名片/全局三级
5. 配置读取带 60 秒缓存，修改后立即失效本进程缓存
6. 验收测试 ⑩ 中限流部分通过

## 必须通过

scripts/check.sh 全部通过

## 交付

- 代码 + 测试 + 交付报告
- 交付报告写入 `tasks/reports/T12.md`（格式见 AGENTS.md），提交到任务分支 `feat/T12-<英文短名>`
- 回复：“T12 已交付，分支 feat/T12-…，报告 tasks/reports/T12.md”

## 契约提醒

接口字段已在 T10 冻结。实现时删除对应接口的 `NotImplementedError` 占位，不改请求/响应字段；确需修改先写 ADR 草稿并停下等待确认。
