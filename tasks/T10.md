# 任务 T10：全量接口契约（契约冻结，把关点 G2）

| 项 | 内容 |
|---|---|
| 角色 | 后端智能体 |
| 阶段 | 阶段 1：功能并行开发 |
| 参考工作量 | 2 天（按人天估算，智能体通常更快） |
| 开工条件 | T08（样板链路审查（把关点 G1）） 已合并到 main |
| 依据 | 开发方案 §8、§9；工程框架方案 §6 |
| 接口 | 全部（契约） |
| 数据库 | — |

## 目标

一次性定义一期全部接口的请求/响应模型和路由签名（函数体返回 501），导出 openapi.json。之后前端据此生成类型、用 Mock 并行开发，集成智能体据此写验收测试。

## 允许修改

- `server/app/modules/*/schemas.py`
- `server/app/modules/*/router.py`
- `server/app/core/errors.py（登记错误码）`
- `contracts/`
- `apps/*/src/api/generated/`

## 不得修改

apps/（生成目录除外）、server/tests/acceptance/、scripts/、tasks/BOARD.md；server/app/core/ 除非任务卡明确允许

## 验收标准

1. 覆盖开发方案 §9.1–9.3 的全部接口（T06 已实现的除外）；每个接口有 operation_id、请求模型、response_model、可能的错误码（写在 responses 中）
2. schema 字段与开发方案 §8 数据模型一致；snake_case；分页统一 Page[T]；时间字段为带时区的 datetime；手机号在列表类响应中为脱敏字段
3. 函数体统一 `raise NotImplementedError`，全局处理返回 501 与错误码 NOT_IMPLEMENTED
4. SSE 接口：在 description 中写明事件格式（开发方案 §9.4），并在 schemas 中定义 delta / lead_prompt / done / error 各事件 data 的模型，供前端生成类型
5. 运行 gen-api.sh：两端 generated 生成成功，前端 typecheck 通过
6. 交付报告附接口清单表：方法、路径、operation_id、请求、响应、错误码、实现任务编号
7. **你审核接口清单与 openapi.json，签字“G2 通过”。此后修改契约必须先写 ADR 并经你确认**

## 必须通过

scripts/check.sh 通过
