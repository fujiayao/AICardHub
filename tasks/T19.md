# 任务 T19：员工、企业信息与 AI 模板管理

| 项 | 内容 |
|---|---|
| 角色 | 后端智能体 |
| 阶段 | 阶段 1：功能并行开发 |
| 参考工作量 | 2 天（按人天估算，智能体通常更快） |
| 开工条件 | T11（鉴权：员工与管理员登录） 已合并到 main |
| 依据 | 开发方案 §4.2、§5.3、§9.3 |
| 接口 | employee_*、company_*、product_card_*、template_* |
| 数据库 | ai_template、assistant（如 T06 未建） |

## 目标

实现管理员侧的员工管理、企业信息、产品卡片、AI 模板接口；新建员工自动生成名片与 AI 助手。

## 允许修改

- `server/app/modules/employee/`
- `server/app/modules/company/`
- `server/app/modules/template/`
- `server/app/modules/assistant/（仅创建默认助手的 service 函数）`
- `server/tests/`

## 不得修改

apps/（生成目录除外）、server/tests/acceptance/、scripts/、tasks/BOARD.md；server/app/core/ 除非任务卡明确允许

## 验收标准

1. 员工：列表（分页、搜索）、新增、编辑、Excel 导入（返回逐行结果）、重置密码、停用、转交访客与线索（`employee_*`）
2. 新增员工时自动：生成 card_code 与名片、按默认模板生成 AI 助手（替换 {姓名}{职位}{部门}{公司简称}{负责业务}）、渲染 persona.md / profile.md
3. 企业信息单行读写、产品卡片增删改与排序（`company_*`、`product_card_*`）
4. AI 模板增删改、设为默认（`template_*`）
5. 修改企业信息或模板后，受影响名片的 profile.md / persona.md 重新渲染
6. 管理员查看与代改：`GET/PUT /admin/cards/{code}`、`GET/PUT /admin/cards/{code}/assistant`
7. 验收测试 ⑧ ⑨ 通过

## 必须通过

scripts/check.sh 全部通过

## 交付

- 代码 + 测试 + 交付报告
- 交付报告写入 `tasks/reports/T19.md`（格式见 AGENTS.md），提交到任务分支 `feat/T19-<英文短名>`
- 回复：“T19 已交付，分支 feat/T19-…，报告 tasks/reports/T19.md”
