# 任务 T41：持续审查与合并（循环任务）

| 项 | 内容 |
|---|---|
| 角色 | 集成与质量智能体 |
| 阶段 | 阶段 1：功能并行开发 |
| 参考工作量 | 贯穿阶段 1（按人天估算，智能体通常更快） |
| 开工条件 | T08（样板链路审查（把关点 G1）） 已合并到 main |
| 依据 | 工程框架方案 §13.4；本计划 §5.4 |
| 接口 | — |
| 数据库 | — |

## 目标

每当有任务提交交付报告，按清单审查，通过则合并到 main 并重新生成契约，不通过打回。

## 允许修改

- main 分支合并操作
- `tasks/BOARD.md`
- `tasks/reports/`

## 不得修改

业务实现代码（server/app/、apps/*/src/），只能打回给负责角色修复

## 验收标准

1. 每次审查在对应交付报告末尾追加“审查结论：通过 / 打回 + 问题列表”
2. 合并后在 main 上运行 gen-api.sh 与 check.sh，全部通过才更新看板为“已完成”
3. 合并涉及数据库迁移或接口变更时，在看板备注并通知另外两个角色执行 `git rebase main`
4. 发现跨角色问题（例如接口字段不合理）时，写 ADR 草稿交你决定

## 必须通过

每次合并后 main 上 check.sh 通过

## 交付

- 审查结论 + 看板更新
- 交付报告写入 `tasks/reports/T41.md`（格式见 AGENTS.md），提交到任务分支 `feat/T41-<英文短名>`
- 回复：“T41 已交付，分支 feat/T41-…，报告 tasks/reports/T41.md”
