# NFC 贴纸写入与采购验收

## 产品规则

长期员工贴纸写固定 HTTPS：`https://{受控域名}/c/{card_code}?s=nfc`，默认不带活动 `e`。活动参数会随着活动结束失效，不应写进长期贴纸。临时展会贴纸如需带 e，写入前必须显示失效时间和“到期后不能按此活动归因”的提示。

贴纸只存 NDEF URI，不存员工登录凭据、JWT、访客 token、私有资料或任意原生 App scheme。固定短链支持员工整体停用；它不支持逐张贴纸挂失、换绑员工或不重写换人。若未来要做这些功能，需另建 tag alias 和绑定生命周期，不得用 UID 作为当前业务能力。

## 安卓写入状态机

```text
idle → emulate → idle
idle → read → idle
idle → write → verify → idle
```

`emulate`、`read`、`write`、`verify` 互斥。写贴纸时停止 HCE 和其他 reader mode；页面退出、超时、进程冷启动、写入失败都回到 `idle`。写入前显示姓名、公司、目标短链和标签已有内容，用户确认后才写。

使用 Android `Ndef` 连接标签，读取 `isWritable` 和 `getMaxSize()`；用 `NdefMessage.toByteArray().size` 与实际最大容量比较。不能仅按 URL 字符数判断，也不能把 HCE 示例的 255 字节上限套到 NTAG21x。写后重新读取 NDEF，确认 URI 与目标完全一致，才显示成功。失败时分别提示：非 NDEF、只读、容量不足、标签移开、写入失败、回读不一致。

首版不提供永久只读锁定操作。若以后增加，必须独立设计、明确不可逆并另行确认；不能把锁卡混入普通写入按钮。已有内容不为空时，本次覆盖必须显示原 URI 与新 URI 并取得本次用户确认；失败后记录标签内容可能已变化，不宣称原内容必然保留。

首批支持可写且已 NDEF 格式化的标准标签；未格式化标签提示暂不支持并联系供应商提供 NDEF 样品，不自动格式化未知标签。原始扇区、门禁复制和 UID 修改不在该功能内。

## 采购候选

| 候选 | 标称用户区 | 用途判断 |
| --- | ---: | --- |
| NTAG213 | 约 144 bytes | 优先样品；短 HTTPS 短链通常够用，但必须按编码后的 NDEF 实测 |
| NTAG215 | 约 504 bytes | URL 变长、需要更宽余量时评估 |
| NTAG216 | 约 888 bytes | 大容量备用；不因容量大就默认更兼容 |

采购询价必须写明：芯片型号与真伪/来源、普通或抗金属、外形尺寸、表面材质、NDEF 是否预格式化、可写状态、批次和 UID 是否仅做采购抽检、读写次数、温度/粘贴条件、无线充电和金属背板影响、是否要求可印刷。AICardHub V1 不把 UID 写入业务数据库，也不做物理库存绑定。

## 到货抽检

每个芯片型号、材质和批次至少抽检 20 张：

1. 安卓助手写入同一合成 HTTPS 短链。
2. 立即回读，比较 NDEF URI、实际字节数和目标值。
3. 用至少 3 台安卓和 3 台 iPhone 读取并打开短链；记录机壳、金属表面、无线充电位置和天线方向。
4. 重复覆盖写入（仅对未锁卡样品），检查只读/容量/失败提示。
5. 断网时分别记录“标签已读取”和“网页无法加载”，恢复网络后重试。

抽检报告必须保存芯片、批次、机型、系统、结果和失败原因。未完成抽检的批次只能标记 `awaiting_hardware`，不能进入支持名单。采购数量、单价、供应商和印刷稿不由 agent 自行下单，需负责人另行确认。
