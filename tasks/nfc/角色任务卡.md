# AICardHub NFC 角色任务卡

每个 agent 只读取自己的任务卡、共享契约和相关项目文档。完成标准必须逐条回传，不能用“代码已写”替代验收证据。

## 共享契约：派工前由总控冻结

- 公开 NFC 内容：受控 `public_base_url` + `/c/{code}?s=nfc`；手机临时展会可追加有效 e；长期贴纸无 e。URL 只包含公开数据。
- 新接口：`GET /api/v1/me/card/share-link?s={Source}&e={optional_positive_integer}`，Staff Bearer、仅本人；响应 `{short_url:string,source:Source,campaign_id:number|null}`；默认 s=link，NFC 调用显式指定 nfc。后端生成最终 OpenAPI 后记录 hash，生成前不手写客户端假装已接通。
- App Link：`{public_base_url}/share/nfc?code={encoded_code}&mode={emulate|write}&e={optional_id}`；默认 emulate。mode 仅表示建议打开的界面，不自动执行写入/模拟；用户预览确认后操作。本期 write 仅支持长期固定链接并拒绝 e；临时活动参数只用于手机 emulate，不实现临时活动贴纸。
- 安卓 URI 解码采用一次明确解析，验证 origin、部署前缀、路径段和参数；使用 URL 库，不使用字符串包含判断域名。拒绝用户名密码、非 HTTPS、额外跳转参数及不受信任目标。服务器重定向限制在同一允许的发布来源。
- 原生验证复用 `/api/v1/public/cards/{code}` 及有效活动 e；成功状态才允许开始。配置页/主动回读不会主动上报 visit；用户打开普通名片页后由现有 H5 记录访问。
- 原生能力分别检查 NFC读写、HCE支持、系统开关；H5 不凭 UA 判断硬件支持。首版采用独立 App，不创建 H5 任意 JS 原生桥。
- 总控冻结实际域名/部署前缀、包名、证书指纹、min/target SDK、参考库提交及许可证、原生依赖版本和构建工具。未定值保持待填，不发布占位值。
- 记录任务预算和并发上限；建议合成冒烟 120 秒、实现任务每 30 分钟交接状态，检查点不等于强制失败。同因两次失败按执行包切换路径。

## 总控 / 集成

范围：任务编排、worktree、契约冻结、合并、报告和发布门槛。允许修改 `tasks/nfc/`、`docs/NFC手机名片接入与功能补充方案.md`、相关 ADR、集成报告。不得替 worker 直接改业务实现来绕过所有权。

完成条件：波次依赖清楚；每个提交通过文件所有者审查；基线和结果提交可追溯；软件、APK、手机射频、贴纸射频、部署状态分别有证据。

## 后端 / 契约 agent

建议模型：先用已通过工具冒烟的 GPT 路由；不要凭品牌名判断可用性。

允许目录：`server/app/modules/workspace/` 相关路由/schema/service/media；对应 `server/tests/`；由它独占导出 `contracts/openapi.json`，H5/后台 owner 分别生成本端客户端，不与后端同时修改前端文件。

任务：新增轻量 `GET /api/v1/me/card/share-link`（operation_id `me_card_share_link`），返回 `{short_url,source,campaign_id}`；复用 `s=nfc` 和活动校验；抽取 URL 构造，避免海报/字体依赖；补根路径、`/aicardhub/`、员工隔离、停用名片、活动过期、来源参数、无开放重定向测试；为 `/c/{code}` 增加合适的 `Cache-Control: no-store` 回归。

完成条件：schema 先于路由；导出 OpenAPI，前端 owner 运行各端生成流程并回传 hash；测试真实执行并记录；无迁移；不得接受 `employee_id`、JWT 或任意 URL 作为请求参数。

## H5 agent

建议模型：已通过工具冒烟的前端执行器。

允许目录：`apps/h5/src/pages/staff/card/`、`apps/h5/src/pages/share/`、`apps/h5/src/platform/`、必要的路径工具和前端测试；不得手改 `api/generated`。

任务：B2/B4 增加手机 NFC、写入贴纸、iPhone 接收说明、安卓助手入口、复制配置链接和备用二维码；NFC URL 使用 `s=nfc`，二维码 `s=qr`，普通分享 `s=link`；活动 e 只用于明确的临时场景；普通浏览器不伪报硬件状态；访客 `/c/*` 不被 App Link 接管。

完成条件：基于真实生成客户端；Vue 3 `<script setup lang="ts">`；文件不超过项目限制；390×844 截图；iPhone 文案只承诺接收，不提供无效的 NFC 发卡开关；链接、二维码、安装失败路径均可操作。

## Android agent（NFC-03 + NFC-06 唯一 owner）

建议模型：长上下文、工具调用已验证的 GPT 路由。该 agent 独占 `apps/nfc-android/`，不得与其他可写 agent 并发修改。

任务顺序：先最小 HCE Type 4 URI 模拟与接收诊断，再加入实体贴纸读写。状态机固定为 `idle / emulate / read / write / verify`，模式互斥；写贴纸时停止 HCE，验证后回到 idle。HCE 使用标准 NDEF URI 和 APDU；贴纸使用 Android `Ndef`，不要把 Type 2 标签写入当作 HCE。

贴纸写入必须校验受控 HTTPS 域名、`/c/{code}?s=nfc` 路径、编码后的实际 NDEF 字节数与 `Ndef.getMaxSize()`；写后回读并逐字节/URI 校验。覆盖只读、非 NDEF、容量不足、移开过早、失败和不一致。默认不锁卡；锁卡若未来提供必须独立操作并明确不可逆。

完成条件：可构建 APK；固定包名、目标 SDK、许可证和依赖清单；无 token；进程退出、过期、锁屏/冷启动按方案关闭；有协议单元/仪器测试或明确说明无法在模拟器完成；设备结果与构建结果分开。

## 后台 / 发布 agent

允许目录：`apps/admin/src/views/Scope.vue`、必要菜单文案；由总控负责部署模板、APK 发布清单和域名根 `/.well-known/assetlinks.json` 合并。

任务：将状态拆成手机分享、贴纸写入、物理库存/绑定；展示已验证设备与 APK 版本，不伪报全员支持；补帮助入口和回退方式。App Link 只关联 `/share/nfc`，不关联 `/c/*` 或 `/card/*`。

完成条件：旧站根路径、AICardHub 子路径和已有 assetlinks 内容不受影响；未发布证书指纹时只提交模板，不写假值。

## QA / 独立复核 agent

只读复核已集成提交与报告；新增测试或报告时遵守任务允许范围，不修改 acceptance 测试。设计三条验收链路和负例：NDEF 分段/超长、活动过期、停用、无网络、HCE 冲突、标签只读、容量不足、写后回读不一致、移开过早、金属干扰。验收时记录机型、系统、NFC 开关、锁屏、钱包/其他 HCE、标签芯片和批次。

完成条件：自动检查输出、设备矩阵、失败复现与下一定位点齐全；未测组合写明 `awaiting_hardware`。
