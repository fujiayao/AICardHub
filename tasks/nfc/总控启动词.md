## 总控步骤

1. 记录当前 HEAD、工作区改动、OpenAPI hash、每个 worktree 路径和文件所有权。保留用户已有未提交改动。
2. 在 Magpie 路由下为每个拟用执行器做一次合成 scratch 工具闭环：创建并读回一个固定 marker；记录模型 ID、协议、工具调用、退出码和耗时。失败两次同因就换已验证路由并保留记录，不反复重试。
3. 只按波次派工：先 NFC-00/NFC-01/QA 用例；NFC-01 契约冻结后再派 NFC-02、NFC-03/06；最后 NFC-04、NFC-05。
4. Android 的 NFC-03 与 NFC-06 使用同一个 owner，按顺序修改 `apps/nfc-android/`。若另有协议审查 agent，只读 Android 核心目录，不与 owner 并发写 Manifest、Gradle、HCE service 或模式控制器。
5. 后端是唯一 schema/OpenAPI 导出者；H5 只能使用生成客户端；后台不修改 API 契约。任何超出任务卡的文件变更先停下，写入阻塞记录。
6. 每个 worker 完成后必须回传：修改文件、基线/结果提交、依赖、测试命令与真实输出、未测项、下一任务依赖。总控先审查再合并。
7. 将五种状态分开记录：软件检查、APK 构建、手机 NFC 射频、实体贴纸射频、部署。没有设备或样品时只能写 `awaiting_hardware`，不得写 accepted。
8. 最终由 QA 按三条链路分别验收：手机 HCE→安卓/iPhone；安卓写贴纸→回读一致；贴纸→安卓/iPhone→短链/H5。二维码成功不能替代 NFC 射频证据。

## Magpie 调度纪律

Magpie 只负责模型路由，执行器负责文件、命令和生命周期。不要假设存在通用的 Magpie `/tasks` 或 `/agents/run` API。使用已核对的本机 `codex exec`、`claude -p` 或项目实际提供的执行入口，并把任务正文写入 prompt 文件后通过标准输入交付。

模型 ID 只能从本轮 `http://127.0.0.1:3425/v1/models` 和实际冒烟结果中选择。候选角色见 `角色任务卡.md`，不代表已经验证可用。生产模型配置与开发 agent 路由分离。任何真实 key、员工资料、私有知识、设备证书私钥都不得进入 prompt、报告或 Git。

## 关闭条件

只有以下全部具备证据时才可以将本轮标为 `accepted`：代码检查、OpenAPI/前端生成结果、APK 构建和签名清单、三类 NFC 真机矩阵、贴纸批次抽检、旧站和部署路径回归。否则将具体状态写成 `software_done`、`awaiting_hardware` 或 `changes_requested`，并保留下一步。
