## 当前执行安排

**总控的原生子代理正在使用 GPT 模型开发并交付，继续按现有所有权推进。DeepSeek Harness 的失败不阻塞业务开发、合并或本地测试。**

| 执行方式 | 本轮状态 | 后续安排 |
|---|---|---|
| 总控原生 Codex 子代理 / GPT | 总控确认实际运行并交付 | 继续当前任务，不干扰、不重复派发 |
| DeepSeek Harness headless | 项目隔离、help/schema、执行器启动已验证；首个模型请求失败，工具闭环未通过 | 停止该路由重试，保留证据 |

Magpie 负责模型发现、路由和协议转换。目录中的模型、路由组以及 Agent 设置行，都不能替代执行器的进程、工作目录、工具和任务生命周期。

## 选择正确入口

下表的命令形态由本机 help 核实；执行任务仍须由总控指定范围、时限和文件所有权。

| 执行器 | 入口 | 工作目录与模型 |
|---|---|---|
| Codex CLI | `codex exec` | `-C` 指定工作根目录，`-m` 指定模型；角色文件与父会话控制子代理 |
| Claude Code | `claude -p` | 从指定 cwd 启动，`--model` 指定模型，`--agents` 定义会话角色 |
| DeepSeek Harness | `dsh --profile headless` | 调用目录是默认 workspace；模型由 profile/patch 配置 |

本机核查版本分别为 Codex CLI 0.169.0、Claude Code 2.1.325、DeepSeek Harness 0.2.2-rc.3。版本变化后先重新核对 help，不能沿用旧参数或旧功能开关状态。

DeepSeek Harness Desktop 安装包自带官方命令，即使 PATH 中找不到 `dsh` 也不代表未安装。本次确认的入口是 `D:\soft\deepseekHarness\resources\runtime\cli\bin\dsh.cmd`。在其他机器上使用该机器实际安装目录，不复制用户配置或临时下载另一版本冒充本机验证。

Magpie 本机命令名称为 `claude`、`codex`、`dsh` 和 `claude-desktop`。`magpie <agent> <model>` 是修改 Agent 模型设置的命令，不是派发任务。未核实到通用任务派发 API，不猜测 `/tasks` 或 `/agents/run` 等接口。

## 隔离 DeepSeek Harness 的项目配置

### 路径和作用域

以仓库根目录为起点，运行数据全部留在未跟踪目录 `.local/agents/dsh/`：

```text
.local/agents/dsh/
  home/
    profiles/headless/
      package.json          # 官方 CLI 初始化的插件束清单
      cordis.yml            # 官方生成的空根配置
      cordis.patch.yml      # profile 用户层
      audit.patch.yml       # 本项目显式加载的验证覆盖
    sessions/               # 本地执行证据，不提交
    storages/               # 本地运行数据，不提交
  readonly.patch.yml        # 只读任务附加覆盖
  scratch/                  # 合成工具任务工作目录
  evidence/                 # 本地诊断和事件，不整目录提交
```

隔离依靠官方支持的三个入口：

1. 为**子进程**设置 `DSH_HOME=<仓库>/.local/agents/dsh/home`，从而选择项目独立 home。
2. 使用 `--profile headless`，选择该 home 内的 headless profile。首次使用会初始化该 profile。
3. 使用 `--patch <项目覆盖文件>`，对本次进程追加覆盖。该参数必须在 headless 的任务参数之前。

`desktop` 是 Electron 专用保留 profile，不能用 `--profile desktop` 直接复用桌面会话。不要复制全局 desktop profile，也不要设置全局环境变量、修复全局 PATH 或编辑用户 home 中的配置来完成项目验证。

配置层顺序是：插件束 → profile patch → `DSH_HOME` 下的 home patch → 命令行 patch。后层覆盖前层；针对 row 的 `config` 是**整体替换**，不是字段深合并。修改时保留所需完整字段。

### 先核对 help 和 schema

以下展示参数顺序，**不是要求当前再次执行**。应在隔离环境已建立、cwd 为空 scratch 后，通过有时限的宿主运行：

```powershell
# $dsh：当前机器已核实的官方 dsh.cmd 路径。
# $auditPatch：项目 audit.patch.yml 的绝对路径。
# 子进程 DSH_HOME 已指向项目 home，不使用用户默认 home。
& $dsh --help
& $dsh --profile headless --help
& $dsh --profile headless --patch $auditPatch --dump-config-schema
```

`--dump-config-schema` 可能初始化缺失 profile，并导入安装包声明的插件 schema，因此也应在项目隔离目录、有时限地运行。不要以打印完整 composed config 的方式收集用户设置。

本次最终 headless help/schema 均退出 0；schema 有 80 个 `$defs`。最初两次冷启动在 45 秒无输出后停止，后来正常启动。冷启动等待不能记录为模型请求失败。

### 模型与工具配置

本轮 `audit.patch.yml` 使用安装包 schema 已确认的原生 DeepSeek adapter 字段：

```yaml
- id: agent-default-model
  config:
    provider: deepseek-official
    model: liangkeai-gg-g/deepseek-v4.1-flash
    reasoningEffort: low
- id: llm-deepseek
  config:
    baseURL: http://127.0.0.1:3425
    apiKeyEnv: MAGPIE_LOOPBACK_ONLY
    thinking: enabled
    reasoningEffort: low
    maxTokens: 4096
    streamIdleTimeoutMs: 45000
    models:
      - id: liangkeai-gg-g/deepseek-v4.1-flash
        name: DeepSeek audit route
        contextWindow: 131072
        maxTokens: 4096
        inputModalities: [text]
```

上面是本轮故障复现所用路由的配置摘录，**不是完整工具边界配置，也不是可用模型推荐**。模型 ID 是目录原值；不能把上游报错中的内部 ID 当作建议替代值。不要将这些开发验证设置硬编码进产品运行配置。

`baseURL` 使用 loopback 根地址，由原生 adapter 追加 Messages 路径。`apiKeyEnv` 只引用环境变量名；启动方只注入本机无认证网关可接受的非秘密调用标识，本文不提供任何 key 值。若网关后来要求真实认证，停止并由总控确认凭据提供方式，不复制全局凭据。

本轮完整工具边界还关闭了 shell、web、搜索、自动 AGENTS/skills 发现、后台 jobs、fork/workflow、自动 goal、标题模型、模型自动重试、官方 session-log 附送和遥测。合成验证只要求写读一个固定 marker。子代理预设上限为深度 1、同时 1 个，实际因首步失败未启动任何子代理。

后续只读任务必须追加覆盖，并同时选择 `--permission-mode read-only --approval-policy never`：

```yaml
- id: tool-fs
  config:
    read: true
    readImage: false
    write: false
    edit: false
    applyPatch: false
```

`workspace-write` 限制写入，不能证明读取只限 cwd。启动方应采用环境白名单，排除继承的供应商凭据、代理、启动注入变量，隔离用户配置与缓存目录。契约复核只由宿主提供获准的 `contracts/IMPLEMENTATION.md` 文本，不自动收集整个仓库、知识库或业务资料。

headless 的“单次任务”仍可能包含多轮模型和工具调用。宿主必须限制总时间、并发和派生进程；本轮上限为 120 秒，超时只回收自己启动的进程树。`--approval-policy never` 表示需要审批的动作被拒绝，不代表授予无限权限。

## 已知故障与停止条件

| 证据 | 结果 | 判断 |
|---|---|---|
| 总控 Chat Completions 合成探测 | DeepSeek 路由返回 400 | 原始错误正文未记录，不能单独判断原因 |
| 本轮 Messages 合成探测 | 400，3.641 秒，`invalid_request_error` | `unknown provider for model cn/deepseek-v4.1-flash` |
| 本轮真实 dsh headless 工具任务 | 41.548 秒、退出 1，`INVALID_REQUEST` / 400 | 首步模型请求得到同一映射错误 |
| 工具与契约审查 | 工具调用 0 次，marker 未生成 | 工具闭环未通过，未向 DeepSeek 发送契约 |

现有证据指向上游模型映射无法解析，不支持把错误归为 `max_tokens` 不足。**该路由停止重试**；不修改全局 provider，不猜替代 ID，不把 GPT 输出标成 DeepSeek 结果。只有总控确认映射已修复并重新安排验证，才先做合成工具闭环，成功后再做只读审查。

Claude 的额度耗尽来自用户通知，本轮没有服务端 quota 回执。已取消的调用无输出，不能记为已审查或零费用。即使预计重置时间已过，也不主动探测；等主要代码完成后，由总控安排一次预算 1 美元、120 秒、禁 MCP 和写工具的关键复核。
