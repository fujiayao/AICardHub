# 数科 AI 智能名片 · H5 UI 设计规范 v1.0

> 日期：2026-11-14｜范围：访客名片 H5（A1–A5）+ 员工端 H5（B1–B13），共 18 页；管理后台不在本规范内，使用 Element Plus 默认样式即可。
>
> 配套文件：`数科AI智能名片_H5原型.html`（可点击原型，打开后左侧选页面，右侧是本文第 5 章的页面规格）、`数科AI智能名片_业务流程与开发方案.md`（业务、接口、数据模型）。
>
> 本规范是前端开发的验收标准。原型中的人物、公司、产品、数据均为示例，开发时全部来自接口，不得写死。

---

## 1. 设计原则

- 访客端的第一目标是“让客户开口”：AI 分身入口必须在首屏可见，底部“和TA聊聊”常驻；每屏只有一个蓝色主按钮
- 颜色有含义：蓝 = 操作，青绿 = AI，橙 = 需要员工关注（A 级意向、新线索、超时），红只用于角标和错误；不得把这四种颜色挪作装饰
- 普通卡片用白底 + 页面灰底区分层级，不加阴影；只有浮起的元素（AI 分身卡、弹层、对话气泡）用阴影
- 职业照是访客端最重要的视觉资产：A1 头图全宽铺满，底部用品牌深蓝渐变压暗以保证白字可读
- 所有公司信息、产品卡片、模板文案都来自后台；页面上不得写死任何公司业务内容
- 文案用口语、动词开头、说清结果（“保存后访客端立即生效”），错误提示说明原因和下一步，不道歉
- 数字统一用 --font-num（等宽数字）；手机号在列表中脱敏，详情中完整显示，分组显示为“138 0000 6688”
- 适配宽度 360–430px，以 390px 设计；底部操作栏与 Tab 栏预留安全区（env(safe-area-inset-bottom)）

## 5. 页面规格

### 访客名片 H5

客户扫码 / NFC / 链接打开，无需登录。

#### A1 名片首页

- **路由**：`/card/:code`
- **目的**：客户打开名片的第一屏。职业照建立信任，“AI 分身”卡片是最醒目的元素，引导客户开始对话；底部常驻“和TA聊聊”。
- **状态**：默认、微信内点“存通讯录”（A5 浮层）（原型中均可切换查看）

**页面元素**

- 沉浸式头图：真人职业照全宽铺满（高 440），底部深蓝渐变压暗，左上公司 Logo + 简称，右上分享按钮（毛玻璃圆钮）
- 身份信息压在头图底部：姓名 30px 粗体白字、职位｜部门、公司全称
- AI 分身卡片（白底、浮起阴影，覆盖头图下沿）：AI 头像（职业照 + 青绿在线点）、“{姓名}的 AI 分身”、“在线”；开场白气泡（青绿浅底）；3 个引导问题（点击直接带问题进入对话）；主按钮“和TA聊聊”
- 快捷操作 4 宫格：打电话、加微信、存通讯录、导航
- 联系方式列表：手机（复制）、邮箱（复制）、地址（导航）
- 个人简介（≤150 字，无内容则整块不显示）
- 公司介绍卡：Logo、公司全称、一句话定位、简介 3 行折叠 +“展开”
- 主营业务横滑卡片：配图 + 标题 + 一句话说明 +“问问 AI”（带入后台配置的问题进入对话）
- 页脚：“内容由数科官方维护”+“留下联系方式”文字链（打开留资弹层）
- 底部常驻操作栏：电话、微信两个小图标 + 主按钮“和TA聊聊”

**交互**

- “和TA聊聊” / 引导问题 / “问问 AI” → A2 对话页（后两者自动发送对应问题）
- 打电话 → tel: 拨号；加微信 → 底部弹层展示员工微信二维码（长按识别），未上传二维码时隐藏该入口
- 存通讯录：系统浏览器下载 vCard；微信内置浏览器显示 A5 引导浮层
- 导航 / 地址 → 跳转高德地图网页版 marker 链接（带坐标与公司名）
- 分享按钮：支持 navigator.share 时调起系统分享，否则复制“{姓名}｜{职位}｜数科 + 短链”并 Toast“链接已复制”
- 进入页面即上报访问（来源 s、活动 e），离开时上报停留时长

**规则与边界**

- 页面 <title> 固定为“{姓名}｜{职位}｜数科”，用于微信转发卡片标题
- 首屏接口一次返回名片 + 企业信息 + 产品卡片；首屏资源 ≤ 300KB，职业照用 CDN 压缩图（宽 750）
- 名片停用时直接渲染 A4，不出现本页任何员工信息
- 公司字段、产品卡片全部来自后台“企业信息”，员工不可改

**接口**：`GET /public/cards/{code}`、`POST /public/visitor/init`、`POST /public/visits`、`PATCH /public/visits/{id}`、`GET /public/cards/{code}/vcard`

#### A2 AI 对话页

- **路由**：`/chat/:code`
- **目的**：访客与员工 AI 分身对话。流式回答、引导提问、识别意向后插入留资卡片。
- **状态**：空状态、对话中、留资弹层（原型中均可切换查看）

**页面元素**

- 导航栏：返回、居中“AI 头像 +{姓名}的 AI 分身 + 内容由 AI 生成，仅供参考”、右侧电话图标
- 背景：顶部浅青渐变（启用“职业照作对话背景”时为职业照高斯模糊 + 白色蒙层）
- 空状态：大头像、“你好，我是{姓名}的 AI 分身”、开场白；“你可以这样问我”+ 3 个引导问题卡片
- AI 消息：左侧小头像，白底气泡（左上直角），顶部“AI”小标识；支持 Markdown（加粗、列表）；气泡下方“点踩”“复制”
- 访客消息：右侧主色蓝气泡（右上直角）
- 流式输出时末尾显示青绿光标；等待首字时显示三个跳动圆点
- 留资卡片（插在 AI 消息之后）：标题“想进一步了解？”、说明、按钮“留下联系方式”+“直接打电话”
- 输入栏：圆角输入框 + 发送按钮（无内容时置灰），下方免责声明一行
- 留资弹层：称呼、手机（必填）、公司、需求（选填，100 字）；隐私说明勾选；“提交”按钮未勾选时置灰

**交互**

- 发送后立即显示访客气泡，AI 气泡以 SSE 增量渲染；收到 lead_prompt 事件后在该轮回答后插入留资卡片（同一会话最多出现 2 次）
- 点踩 → 图标变实心并 Toast“感谢反馈”；同一条只能点一次
- “留下联系方式” → 打开留资弹层；提交成功 → A3
- 手机号格式校验失败：输入框下方红字“请输入正确的手机号”
- 网络失败：AI 气泡显示“网络不太好，点此重试”；超出限额：显示后台配置的兜底话术 + 员工电话
- 返回名片：保留会话，再次进入恢复历史（同一浏览器）

**规则与边界**

- 每条 AI 消息都要有 AI 标识；免责声明常驻输入栏下方
- 访客发送内容中出现手机号，服务端自动生成线索，前端无需额外处理
- 单次回答展示不限高，但超过 6 行的列表自动折叠为“展开全部”

## 7. UI 验收清单

- 颜色、字号、圆角只使用第 2 章 tokens；页面中搜索不到规范外的色值。
- 访客端 A1 在 390×844 屏幕上，首屏可见：职业照、姓名职位、AI 分身卡片的开场白与至少 1 个引导问题；底部“和TA聊聊”常驻。
- 360px 与 430px 宽度下无横向滚动、无文字溢出；长姓名（6 字）、长公司名（20 字）不换行错位。
- 微信内置浏览器、iOS Safari、安卓系统浏览器三种环境截图与原型一致；微信内“存通讯录”出现 A5 浮层。
- 所有可点击元素点击区域 ≥ 44×44；按钮有按下态。
- 空状态、加载态、错误态都有设计：列表为空用空状态组件；接口失败给出原因和重试。
- AI 回答始终带 AI 标识，对话页免责声明常驻。
- 员工端底部 Tab、消息铃铛角标、页面标题未读数三处数字一致。
- 手机号：列表脱敏、详情完整、显示分组空格。
