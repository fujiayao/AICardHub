# 本地验收操作

状态：开发进行中；以下入口须以最终测试报告中的就绪结果为准。

## 启动

在项目目录运行 `powershell -ExecutionPolicy Bypass -File scripts/start-local.ps1`。首次安装会按锁文件准备依赖；已安装可加 `-SkipInstall`。脚本迁移数据库、准备幂等演示种子、启动API/H5/后台，日志位于`.local/`。

- 访客名片：http://127.0.0.1:5173/card/demo
- 员工登录：http://127.0.0.1:5173/login
- 管理后台：http://127.0.0.1:5174
- API文档：http://127.0.0.1:8000/docs

账号来自`server/local-credentials.json`，该文件仅保存在本机。employee和colleague是两个不同归属的演示员工；admin用于管理。演示公司、资料、联系人均为合成测试数据，验收后可通过后台录入获准内容。

## 建议验收顺序

1. 从访客入口打开名片，核对UI与原型、联系人、主营业务和AI入口。使用360/390/430宽检查。
2. 进入聊天，查看开场白和引导问题，发送一条演示问题。检查流式输出、错误提示、重新进入的历史。
3. 在聊天中发送测试手机号，确认不会自动创建线索；主动打开留资表单，未同意时不能提交，同意后才创建。
4. 用employee登录，查看自己线索、修改状态和备注；改名片后回访客端验证立即生效。
5. 用colleague登录，确认无法查看employee的线索、访客历史和私有笔记。
6. 检查员工助手、知识笔记、导入、试聊、纠错、分享和通知；按最终交付矩阵查看功能完成情况。
7. 后台登录，创建测试员工；新员工首次登录要求改密。检查停用后名片与员工登录状态。
8. 管理公开知识，先草稿、再发布、再撤回，确认访客只能使用当前获准公开的版本。

## 检查报告

运行 `powershell -ExecutionPolicy Bypass -File scripts/check.ps1 -E2E`；浏览器测试入口位于`e2e/browser`。测试是否通过以实际报告为准，脚本存在不代表已通过。

本地Fake模型用于确定性功能测试，界面应标记演示。真实GPT/DeepSeek调用、正式知识正确率、手机微信/NFC和4G性能须单独记录结果。

完成本地验收后，由负责人确认，再准备服务器部署。
