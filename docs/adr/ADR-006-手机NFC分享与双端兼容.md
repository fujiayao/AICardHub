# ADR-006 手机 NFC 分享与双端兼容

日期：2026-11-15。状态：**产品范围已确认，实施方案已整理，代码尚未实施**。负责人明确要求“先兼容苹果端作为接收方，安卓端作为发送和接收方，同时也需要兼容写入 NFC 贴纸”，并要求提供通过 Magpie 调度 agent 的开发执行方案。本次确认覆盖该范围，不包含采购或生产发布执行授权。

## 背景

原项目以 H5 为主，NFC 设计以实体卡为发送载体。当前需求是无需实体卡、独立于第三方平台，以手机分享系统短链，并兼容安卓与 iPhone。源码已有短链、NFC 来源、H5 和数据归因，缺少手机卡模拟能力。

## 范围决策

1. 新增 Kotlin Android 原生伴随应用 `apps/nfc-android/`，基于 Android HCE 模拟 NDEF URI；保持现有 FastAPI、MySQL、Vue/Vant、Element Plus 栈。
2. 员工端 H5 提供导入公开短链、安装与帮助；助手只保存公开链接，首版不新增账号或令牌体系。
3. 复用现有短链及 s/e 来源活动参数，新增不生成图片的轻量 `/me/card/share-link`，无新增数据库表。
4. 首期兼容范围：安卓手机通过 NFC 发送；安卓与 iPhone 接收；安卓助手写入 NFC 贴纸，安卓与 iPhone 读取贴纸。iPhone 发卡和写贴纸不属于首期验收范围，两端均保留二维码/链接分享。
5. 海外 iPhone HCE 需要 Apple 对应资格与授权，独立验证后再决策，不作为本期依赖。不得以 PWA、NameDrop、Web NFC 或苹果钱包通用卡面冒充任意网址卡模拟。
6. 前台、亮屏、解锁、限时启用，退出/冷启动默认关闭。网页成功显示和本地 NFC 读完成分别计量。
7. 所有接口与依赖变更先冻结任务范围和版本；部署包含 Android App Link 域名根关联文件，必须检查对原网站影响。
8. 安卓助手区分卡模拟与读写器模式，互斥切换。写贴纸先检查可写性和实际容量，写后回读验证，首版不提供永久锁定操作。
9. 长期贴纸写员工固定短链和 `s=nfc`，默认不带活动参数。贴纸写入不等于库存、后台绑定、挂失或换人管理；后者另行立项。

## 影响

- 扩展原“H5-only”的交付范围，新增 Android SDK/JDK/Gradle、APK 签名与真机验证工作。
- H5 仍是跨平台产品主体；不新增 React Native、Flutter 或 iOS 原生应用依赖。
- 贴纸写入纳入首期；原实体卡库存、绑定、挂失功能仍保持当前交付状态，不用贴纸写入替代其验收。
- 首版只做来源归因，不提供设备级远程撤销和硬件可信碰触次数。

## 后续范围

如未来要求 iPhone 发卡，应重新验证地区、授权和设备能力；本次不将该能力计入兼容承诺。iPhone 原生写贴纸可独立评估，不能依靠 H5 实现。
