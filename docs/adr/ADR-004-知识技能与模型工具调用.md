# ADR-004 知识技能与模型工具调用

状态：按负责人2026-11-15明确要求实施；参考无线画布zi助手复用指南和对应真实源码。范围仅名片助手能力，不移植画布或动态形象。

## 负责人后续澄清：AI智能名片，不是通用画布助手

负责人看到“协助写作和处理代码”的身份介绍后明确纠正：助手须围绕名片对应企业、岗位和业务领域，不能照搬画布的通用能力定位。此澄清覆盖下文所有可能被理解为无限制通用助手的表述。

名片助手可利用模型理解与相关领域通识，辅助业务了解、合作咨询、需求梳理、商务交流、展会接洽及联系对接；不以知识库无命中为由机械拒答。身份回答应准确介绍当前姓名、公司和职务，不能只说“一个可以写代码的助手”。明显无关任务简短引回名片业务，业务相关技术解释和方案不受影响。实际公司能力、承诺和联系方式仍须公开依据。

## 依据与术语

源参考：`D:/LLM/ComfyUIProject/open-ai-canvas/docs/ASSISTANT_FEATURE_REUSE_GUIDE.md`。其中复制提示词、方案B及头像推荐是参考材料，不构成本任务新增范围。

- Skill是受控的工作方式、适用条件和工具使用说明，不等于事实数据库。
- 知识库是可按需查询的事实资料，不是通用对话的许可名单。
- 工具调用是模型产生结构化调用、服务端授权执行、结果回传模型后继续生成的真实闭环；把文字拼进提示词不能假称工具执行。

源`web/src/services/skill-runtime.ts`的`linked-context`会加载SKILL.md和有限关联文件并记录来源；源Agent运行时另有真正工具桥。目标保留自己的FastAPI/MySQL/Vue技术栈，用现有模型客户端实现相应能力，不搬React/Go/Node运行平台及其凭据。

## 决定

1. 模型主导正常回答。移除按“合同、价格、身份”等词直接返回固定模板的业务分支；由明确的技能和系统规则区分通用解释与公司实际承诺。
2. 基础身份始终可用：当前公开名片的姓名、职位、所属公司，不依赖MD命中。具体联系方式以真实公开字段为准。
3. 提供只读的知识查询、资料读取和公开名片能力，模型按问题调用。服务端绑定当前名片，不接受模型替换所有者或提供任意路径；每次读取验证公开、批准、未删除及范围。
4. 不提供自动写线索、发消息、改数据、shell、任意文件或互联网访问工具。留资仍由用户主动同意提交，不能因模型声称已转交就视为已完成。
5. 兼容原有HTTP和SSE。工具执行可通过脱敏日志验证，不能用定时器或假状态冒充。引用仅来自实际取得并传给模型的资料，不将通用回答或公开名片伪造成MD引用。
6. 有明确工具轮数、调用数、参数/结果长度、回答长度和总时间预算；禁止无界循环。取消和异常关闭上游；内容或工具执行开始后不得自动切换供应商重放。
7. 取消200字机械截断；默认简洁，任务需要时允许结构化展开，在合理上限内完成。达到上限应明确报告，而非截断后伪造完整成功。

## 验收

模型实际回答“你是谁”“你能干什么”、通用写作/代码/合同科普；真实企业资料题触发查询及必要读取，并返回模型完成事件。无匹配资料不妨碍通用能力，也不编造公司事实。自动测试用Fake/合成SDK事件验证两种模型协议，真实供应商验证单独记录。

保留跨访客会话隔离、跨名片知识隔离、撤销公开即时生效、工具参数错误、预算耗尽、重复调用、取消与流中断回归。不能以编译通过代替真实工具调用证据。最终需明确用户打开的验收入口及是否仍连旧服务。
