# ADR-003 通用对话与访问归因解耦

状态：根据负责人2026-11-15在本会话的明确要求执行。负责人要求助手不只限于Markdown内容，并取消“访问记录与会话不一致”对正常使用的限制。

## 问题与证据

对真实访客名片提问“你怎么联系你”，返回固定“目前没有足够的批准公开资料”，SSE完成事件标记`model=policy`，不是供应商模型。旧实现把检索无命中等同于不可回答，直接跳过大模型。详见`tasks/reports/ai-conversation-fix/before.json`。

访问记录用于来源统计，会话用于连续对话，两者生命周期不应强制一致。刷新产生的新访问记录，不应让同一访客原有会话无法继续交流或提交联系信息。

## 决定

1. 知识检索是增强上下文，不是调用模型的前置许可。正常问题即使没有命中资料，仍请求配置的大模型。
2. 通用知识、日常交流、表述整理及沟通建议允许使用模型能力。涉及公司、人员、业务案例、联系方式等特定事实时，以当前公开名片和批准公开资料为准；未知事实不可编造。通用知识不冒充企业制度或承诺。
3. 公开名片的结构化身份及联系字段作为独立事实上下文，不依赖词语匹配命中Markdown。只传公开投影的必要字段，不传登录手机号、密码、访问令牌、私人笔记等内部数据。
4. 未公开或未批准的知识仍不可向访客或外部模型泄露。取消“仅MD”不等于放开全部内部资料。知识引用只能对应真正检索到的资料，不能为结构化字段或常识伪造文档引用。
5. 访问记录是辅助归因，不再要求请求中的visit_id与会话保存的visit_id字面相同。可信会话归因优先，同一访客刷新产生的记录差异不得阻断主流程；不得借此关联其他访客、名片或错误活动。
6. 会话所有权、名片有效性、显式留资同意、模型故障处理继续保留。自动测试仍使用FakeLLM；真实供应商验证单独记录，发生错误不能冒充成功。

## 兼容与验收

保持现有HTTP/OpenAPI及SSE事件字段兼容，无计划数据库迁移。新增无知识模型调用、结构化公开字段、通用问题、刷新后访问归因、越权隔离回归；旧测试中与本次需求明确冲突的“无知识不得调用”断言应按新规则替换，但不能削弱未批准资料隔离断言。

本决定不授权自动修改或发布原始知识库，不执行部署，不承诺联网搜索能力。模型的通用回答可能不准确；无法核实的实时或专有信息应明确说明。
